# 🔵 PRÁCTICA 4.2 — Task 2: Borrar registros de máquinas Windows usando varias utilidades

**Clear Windows Machine Logs using Various Utilities** *(Borrar registros de máquinas Windows usando varias utilidades)*

### Explicación del ataque (para decir en el video)

Esta práctica es sobre "cubrir huellas" (covering tracks), que es una de las últimas fases de un ataque: una vez que ya hice todo lo que quería en el sistema de la víctima, quiero borrar la evidencia de que estuve ahí. Los logs (registros) del sistema guardan eventos como cambios de dispositivos, drivers, operaciones del sistema, y básicamente todo lo que ocurre en la máquina — si un atacante deja esos logs intactos, un investigador forense puede reconstruir exactamente qué hizo. Voy a usar tres utilidades distintas de Windows para esto: primero un script por lotes que limpia el visor de eventos, después el comando `wevtutil` para listar y borrar logs específicos, y por último `cipher`, que sobrescribe el espacio de disco donde estaban archivos ya borrados, para que no se puedan recuperar con herramientas forenses.

## 1️⃣ Preparación

**1.1 —** Enciendo **Victima1** e inicio sesión con el usuario `Luis Mendez 20250826`, contraseña `windows`.

**1.2 —** Muestro en cámara usuario, fecha y hora *(rúbrica)*.

## 2️⃣ Adaptación — el archivo Clear_Event_Viewer_Logs.bat no está disponible

**2.1 —** El manual pide navegar a `E:\CEH-Tools\CEHv12 Module 06 System Hacking\Covering Tracks Tools`, ejecutar el archivo `Clear_Event_Viewer_Logs.bat` como Administrador, y ese script se encarga de limpiar los logs de seguridad, sistema y aplicación automáticamente.

**2.2 —** Confirmé con el comando `dir` que esa unidad `E:\` no existe en mi máquina, así que no tengo ese archivo. Como no puedo inventar el contenido exacto de ese script, voy a lograr el mismo resultado de forma manual usando `wevtutil` — que es justamente la segunda utilidad que enseña este mismo manual más adelante, así que no me salto ningún objetivo de la práctica, solo cambio el orden y la herramienta.

## 3️⃣ Abrir la Consola de comandos (Command Prompt) como Administrador

**3.1 —** Hago clic en el ícono de búsqueda (**Buscar**) en la barra de tareas o el menú Inicio, escribo `cmd`, y cuando aparece **Símbolo del sistema (Command Prompt)** en los resultados, hago clic derecho sobre él y selecciono **Ejecutar como administrador (Run as administrator)**.

**3.2 —** Aparece la ventana de **Control de cuentas de usuario (User Account Control)** preguntando si quiero permitir que esta aplicación haga cambios; hago clic en **Sí (Yes)**.

**3.3 —** Se abre una ventana de **Símbolo del sistema (Command Prompt)** con privilegios de **Administrador**, confirmado en el título de la ventana.

## 4️⃣ Listar los registros de eventos con wevtutil

**4.1 —** En la consola, escribo el siguiente comando y presiono **Enter**:

```
wevtutil el
```

> Nota del manual: `el` es la abreviación de `enum-logs` (enumerar registros) — este comando muestra la lista completa de nombres de logs de eventos disponibles en el sistema.
> 

**4.2 —** Veo en pantalla una lista larga con todos los nombres de los registros de eventos del sistema (por ejemplo `Application`, `Security`, `System`, entre muchos otros).

## 5️⃣ Borrar registros específicos con wevtutil

**5.1 —** Ahora escribo el siguiente comando para borrar el log del **sistema**, y presiono **Enter**:

```
wevtutil cl system
```

**5.2 —** De la misma forma, borro los registros de aplicación y seguridad usando el mismo comando con distintos nombres de log:

```
wevtutil cl application
wevtutil cl security
```

> Importante: `wevtutil cl` **no muestra ningún mensaje cuando funciona bien** — al presionar Enter, la consola simplemente vuelve directo al símbolo `C:\Windows\system32>` sin decir nada, y eso es la señal de que el registro se borró correctamente. Solo aparecería un mensaje de error en rojo si algo sale mal (por ejemplo, si escribo mal el nombre del log). Así que si no sale nada, no me preocupo — vuelvo a la línea de comandos y sigo con el siguiente.
> 

> Nota del manual: `cl` es la abreviación de `clear-log` (borrar registro), y el nombre después del comando (`system`, `application`, `security`) es el log que quiero borrar. `wevtutil` es una utilidad de línea de comandos para obtener información sobre registros de eventos y sus publicadores. También sirve para instalar y desinstalar manifiestos de eventos, hacer consultas, exportar, archivar, y borrar registros.
> 

## 6️⃣ Sobrescribir archivos borrados con Cipher

**6.1 —** En la misma consola, escribo el siguiente comando y presiono **Enter**:

```
cipher /w:C:
```

> Nota del manual: `cipher /w:[Unidad o Carpeta o Ubicación de archivo]` sobrescribe los archivos ya borrados en la unidad, carpeta o archivo indicado — aquí lo hago sobre toda la unidad `C:`. Se puede correr sobre cualquier unidad, carpeta o archivo específico.
> 

**6.2 —** La utilidad **Cipher.exe** empieza a sobrescribir el espacio de los archivos borrados: primero con puros ceros (`0x00`), después con puros 255 (`0xFF`), y finalmente con números aleatorios — voy viendo puntos que avanzan en pantalla mostrando el progreso.

> Nota del manual: **Cipher.exe** es una herramienta de línea de comandos integrada en Windows que sirve para borrar de forma segura un bloque de datos, sobrescribiéndolo para evitar que se pueda recuperar. Este comando también ayuda a cifrar y descifrar datos en particiones NTFS.
> 

> Nota del manual: cuando un atacante crea un archivo de texto malicioso y lo cifra, en el momento del cifrado se crea un archivo de respaldo (backup). Si el proceso de cifrado se interrumpe, ese archivo de respaldo se puede usar para recuperar los datos. Al completarse el cifrado, el archivo de respaldo se borra, pero ese archivo borrado se podría recuperar con software forense y usarse en una investigación. Para evitar la recuperación de datos y cubrir sus huellas, los atacantes usan `Cipher.exe` para sobrescribir los archivos borrados.
> 

**6.3 —** Como este proceso puede tardar bastante según el tamaño de la unidad, presiono **Ctrl+C** en la consola para detener el proceso de cifrado unos segundos después de que empieza, apenas se ve que arrancó.

> Nota del manual: el tiempo que toma sobrescribir el archivo, carpeta o unidad borrada depende de su tamaño.
> 

> Importante: no conviene dejar correr `cipher /w:C:` por mucho tiempo. Este comando recorre **todo el espacio libre** de la unidad `C:` y lo sobrescribe — pero como el disco de la máquina virtual es un archivo (`.vmdk`) de crecimiento dinámico dentro de mi disco físico, mientras más tarda escribiendo, más tiene que crecer ese archivo en mi disco real para contener toda esa escritura. Si lo dejo correr mucho tiempo puede llegar a agotar el espacio libre de mi disco físico. Por eso lo interrumpo rápido con Ctrl+C, apenas lo necesario para demostrar que el comando funciona.
>
